# 秋招智能管理助手（混合模式）

## 分工

| 入口 | 职责 |
| --- | --- |
| **控制台** `qiuzhao/console/run.ps1` → http://127.0.0.1:8765 | 今日待办、投递 CRUD、学习任务、贴链接入队、冲突/ICS |
| **Obsidian** | 面经/知识库长文复习；Markdown 仍为真相源 |
| **Cursor Agent（本 Skill）** | 消费 `07_任务/agent队列.md`；上网深挖 JD；面经图片整理 |
| **面试准备** `qiuzhao-interview-prep` | 对某一岗：分析 → 面经 → 自我介绍 →（可选）口述卡与模拟卷（`08_` + `09_口述题答`） |
| **口述题答** `qiuzhao-oral-qa` | 默认按需润色（一次一题）；必练短名单 + 答法模版；模拟卷 / 豆包导出 |
| **答案清洗** `qiuzhao-answer-clean` | 同步答案框架（每节一例）+ 原稿→标准答；`06_知识库/面经答案/` |

用户日常**不必背口令**。仅当控制台有「待处理」时，说一句 `处理控制台任务`。  
某公司某岗位要做面试材料时，改用 **`qiuzhao-interview-prep`**（勿与本 Skill 的入库/队列流程混为一谈）。练口推荐 **`润色口述：<QID>`**（`qiuzhao-oral-qa`）；答案框架 **`同步答案框架：全部`**，清洗 **`清洗答案：<公司>`**（`qiuzhao-answer-clean`）。

## 云端仓库与笔记真源（强制）

收集秋招与面经时遵守本节。补丁只改本节，并同步 `qiuzhao/DEV.md` 同名节；不另建规则文件，也不靠每次对话粘贴长 prompt。本 Skill 只在对话工作区能读到本仓库时加载。

- **对话主仓库**：选 **work27**（`Alam-100/work27`）。`.cursor/skills/` 与 `qiuzhao/scripts/` 只随这个工作区加载。只选 my-obsidian，这些 skill 不会自动生效。
- **环境**：虚拟机里同时克隆 **work27** 与 **my-obsidian**。只配环境、对话却不把 work27 当工作区，技能不会生效；只选 work27、环境里没有 my-obsidian，就写不进 Obsidian 远程。
- **笔记落点**：写入 my-obsidian 克隆里已经存在的 `秋招/` 相对路径（`qiuzhao_root = vault_root / "秋招"`）。禁止另起目录，禁止把 vault 历史库复制进 work 当第二真源。找不到已有 `秋招/` 就停并说明。
- **分工**：笔记正文以 my-obsidian 为准。work 只更新脚本、`qiuzhao/data/source_links.json`、修改日志。
- **推送**：用户明确说可以直接推 my-obsidian 的 main 时才推 main；否则按该仓库保护规则开 PR。禁止强推。本机备份仍走文末「双重备份」；云端不要用该脚本绕过这条推送边界。

### 处理控制台任务（强制流程）

1. 打开 `秋招/07_任务/agent队列.md`，列出 `状态=待处理` 的行
2. 若无待处理 → 短报「队列为空」，结束
3. 逐条：先标 `处理中` → 按 `意图` 执行（载荷解析）→ 写 `结果摘要` → 标 `完成` 或 `失败`
4. 意图映射：
   - `链接入库`：载荷为空格分隔 URL 列表 → 同链接入库质量门
   - `收集公司`：载荷为公司名，或 `核实:公司|intel_stem` → 收集/重核实
   - `每日情报更新`：执行日更 checklist（含西电校园活动）
   - `宣讲会更新`：`py -3.12 qiuzhao/scripts/fetch_xidian_events.py --write-vault --update-source-links`
   - `宣讲会补录`：载荷为公众号 URL 或「截图」；优先读 `04_情报/宣讲会收件箱.md`，截图目录 `03_面经/_inbox_images/宣讲会/` 或 `04_情报/_inbox_images/宣讲会/`；合并写入 `10_校园活动`（按 `外部ID` 或 `公司+开始+地点` 去重）；**微信验证墙失败则停并请用户截图，禁止空文入库**；处理完截图移入同目录 `_已处理/`
   - `面经图片`：载荷为公司名 → 处理 `_inbox_images/{公司}/`
   - `跟进投递`：载荷为情报笔记 stem → 建进度+面经壳
5. 全部完成后短报：完成数 / 失败数 / 关键笔记链接
6. 可用 `vault_io.update_agent_job` 或直接改表；保持表格列：`id | 创建于 | 意图 | 载荷 | 状态 | 结果摘要`

### 裸 URL 规则（强制）

1. 消息含 URL → **直接当任务**，禁止要求 `类型: 岗位 | url:` 或必须先写口令前缀
2. 用户说了「岗位/JD/校招」→ 走提取岗位；说了「面经/博客/知识」→ 走知识入库；都没说 → 抓取后根据页面判断
3. 多 URL → 逐条处理，汇总结果链接
4. URL 命中 `offerstar.cn/recruitment`、`qiuzhifangzhou.com/campus`、`nowcoder.com/jobs/school/schedule` 或同类校招汇总/日程 → **自动走导入汇总表**（不必先写口令）

### 页面类型（链接分级）

| 类型 | 特征 | 行为 |
| --- | --- | --- |
| **单岗** | 具体 JD / 单岗位详情 | `fetch_url` → 抽字段 → **有实质 JD 才写**情报卡 |
| **汇总表** | OfferStar / 求职方舟 / sma-wiki / 牛客校招日程等列表 | 读表筛线索 → **必须深挖官网投递页拿到 JD** 才入库；列表行本身不写情报卡 |
| **列表待深挖** | 一页多岗、要点进才有 JD | 只深挖与画像匹配的至多 N 条（默认 10）；抽不到 JD 则跳过 |
| **二维码墙** | 仅二维码/小程序/需扫码进群 / 微信公众号投递 | **丢弃不入库**；记来源日志；请用户贴可打开的官网投递 URL |

### 入库质量门（强制）

1. **无实质 JD 不入库**：`岗位简介` 须含可核对的职责/要求正文；仅公司名+岗位名列表不够。**正文 `## 岗位简介` 与 frontmatter 必须同时有 JD**（阅读视图不展示 YAML）
2. **微信公众号 / 扫码墙投递链默认丢弃**（`mp.weixin.qq.com`、明确扫码进群）→ 不写情报卡
3. **汇总表只做候选线索**：方舟/OfferStar/sma-wiki 列表字段（职位摘要、尽快投递）不得单独落 `02_情报库`
4. 截止未知 → 留空 + `需再核实: true`；**禁止编造**截止日
5. 深挖遇登录墙/验证码 → 该条跳过，记日志，**禁止空卡冒充成功**
6. **博士硬门槛不入库**：画像为硕士。官网任职要求**只要博士**（硕士不可投）→ 直接剔除，不写卡、不标观望。判定用 `qiuzhao/scripts/jd_edu_gate.py`。
   - **剔除**：`博士学历` / `获得博士学位` / `博士及以上` / 岗名博士专场（如「研究员-博士」）
   - **仍收**：`硕士或博士` / `硕士/博士` / `硕士及以上` / `博士优先`（硕士可投）

### 群消息收件箱

文件：`秋招/04_情报/群消息收件箱.md`；原文归档 `04_情报/_群消息原文/YYYY-MM-DD.md`。

- 用户把秋招群导出贴到「待处理」，或直接贴进聊天
- 抽出公司 / 校招链 / 内推码；`&amp;` → `&`；实习生链、微信墙、流量卡广告、无关行业（家具/乳业/药房/养殖等）丢弃
- 腾讯文档 smartsheet 只作线索（见抓取第 12 条），不写岗卡
- 已有公司：群链与库内渠道比有效性（内推码 / `shareId` / `recommendCode` 优于裸门户；短链更差）。群链更好则**替换** `_公司.md` 投递渠道；**禁止**把列表页写进岗卡、**禁止**自动建进度
- **岗卡 `投递链接` 必须是单岗 permalink**（见下节「岗卡 permalink」）。群聊几乎都是列表+内推码，只进公司卡
- 新公司：官网校招列表搜 Agent/智能体/大模型应用并点详情，过质量门才入库；**央国企**可宽到 AI 应用/智能投研/大模型应用开发
- 处理后清空「待处理」，结构化表写入「已处理」

## 抓取与回退

1. `python qiuzhao/scripts/fetch_url.py --url "..." --out <tmp.json>`
2. OfferStar：`python qiuzhao/scripts/fetch_offerstar.py --url "..." --out list.json`
3. 求职方舟：`python qiuzhao/scripts/fetch_fangzhou.py --out list.json`（Playwright 读 localStorage；默认筛 `urlType=官网` + 画像关键词）
4. sma-wiki：`python qiuzhao/scripts/fetch_sma_wiki.py --out sma_wiki.json --diff-vault`（默认互联网+27届秋招；读 `RAW_DATA`；解牛客 jump；优先 `--filter-keywords "Agent,智能体,大模型应用"` + 未入库公司）
5. 牛客日程：`py -3.12 qiuzhao/scripts/fetch_nowcoder_schedule.py --batch 1203,1206,1210`（`1203`=提前批，`1206/1210`=正式批；API `list-card`）
   - **深挖补刀**：日程卡只有公司入口时，必须再打开 `nowcoder.com/enterprise/{id}?recruitType=1`（校招 tab）搜 Agent；点进 `jobs/detail/{id}` 抽 JD。勿只信官网「飞凡计划」等方向总岗（易漏具体 Agent 岗）
6. 西电校园活动：`py -3.12 qiuzhao/scripts/fetch_xidian_events.py --write-vault --update-source-links`
   - 权威源：`job.xidian.edu.cn` 宣讲会 / 招聘会（非公众号周报）
   - 公众号「西电科大就业指导服务中心」仅作补录：收件箱 `04_情报/宣讲会收件箱.md`；截图 `03_面经/_inbox_images/宣讲会/` 或 `04_情报/_inbox_images/宣讲会/`（处理后进 `_已处理/`）
7. 汇总线索 → 对投递链深挖（`fetch_url` / Playwright）；**抽到实质 JD 才写情报**
8. `status=ok` 才用正文；否则 Playwright MCP，或停并请粘贴 / 收件箱备注
9. **禁止**整页 HTML 原样入库；**禁止**抓取失败却写空笔记；**禁止**无 JD 入库
10. **JD 去噪（强制）**：写入前用 `qiuzhao/scripts/clean_jd_text.py`（或同等逻辑）去掉重复标题、重复「全职/城市/算法研究」元数据行、列表页残留「立即投递」、以及同一【岗位描述】紧凑/展开双份正文；只保留一份结构化职责+要求
11. **学历门（强制）**：写卡前 `jd_edu_gate.is_phd_only(岗位名, JD)`；只要博士则跳过并记日志，禁止观望入库
12. 同 `来源链接` / `投递链接` / 同公司同招聘计划 → **更新合并**；**不同招聘计划可分卡并存**（提前批 ≠ 正式批）
13. 腾讯文档 smartsheet：Playwright 尝试；失败则请用户导出 `.xlsx` 后说「导入表格」
14. **大厂占位禁止**：官网显示「暂无在招 / 0 岗」、站内 FAQ 仍写过期届别且抽不到当期实质 JD → **删卡不留占位**
