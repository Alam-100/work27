# 面经搜寻（秋招专享）

## 目标

以目标岗位 JD 为范围锚点，系统搜集并综合公开面经。优先回答「该公司该岗位实际重点考什么」，保留来源与不确定性；不把单篇帖子包装成高频规律。入库前必须完成清洗、题干补全、分类与去重。

**广扫模式（1C）**：主控未限定公司时，可同时续挖已有题库公司，并收录**未在情报库出现**的公司真面经（新建 `{公司}-Agent面经题库.md`）；不因「无秋招卡」丢弃实质题干。无对应岗时可不写 `08_`，但须回链综摘索引。

## 路径约定

| 角色 | 路径 |
| --- | --- |
| JD | `秋招/02_情报库/{公司}-{岗位}.md`（或主控指定 stem；广扫时可缺） |
| 本地题库（只列问题） | `秋招/06_知识库/公司面经摘录/{公司}-Agent面经题库.md` |
| 综摘索引 | `秋招/06_知识库/公司面经摘录/牛客综摘-Agent面经.md`（多源拆入库回链） |
| 个人复盘 | `秋招/03_面经/{公司}-面经与复盘.md` |
| 书签入口 | `秋招/04_情报/来源链接库.md` + `qiuzhao/data/source_links.json` |
| 项目手册（可选） | `秋招/06_知识库/DORA面试手册/` |
| 手撕清单（知识点主轴） | `秋招/06_知识库/手撕与算法/高频手撕清单.md` |
| 产出 | `秋招/08_面试准备/{公司}-{岗位}/常见问题与面经汇总.md` |
| 临时 | `qiuzhao/tmp/` |

云端对话的主仓库、环境与笔记真源以 `qiuzhao-assistant`「云端仓库与笔记真源」和 `qiuzhao/DEV.md` 同名节为准。本 Skill 不另起目录。

## 帖子质量门（强制）

| 类型 | 处理 |
| --- | --- |
| **真面经**：分轮次、有具体可考问句（文或图） | 点开全文后抽题入库 |
| **总结/卖课帖**：仅话题频次统计、无实质题干、引流卖课 | **丢弃**；短报记「跳过」；最多作 D 级线索，**不写题库** |
| **广告/无公司无题干** | 丢弃 |

**平台停用：小红书**：已出现机器爬取警告。Agent **不得**打开 `xiaohongshu.com`、不得批量抓取或做任何规避检测。用户人工看帖后可贴题干入库；`小红书-Agent面经题库` 是**公司**题库，与平台入口无关，继续维护。

## 公司与时效筛选（广扫时强制）

| 维度 | 规则 |
| --- | --- |
| **岗位对口** | 只收 **AI Agent / 大模型应用 / Agentic 研发** 及明确含 Agent、RAG、LLM 应用工程的面经；纯前端 / 纯运营 / 无关算法岗丢弃 |
| **时间** | **优先 2026**（标题/正文含「26 秋招 / 暑期 / 实习」或近几个月）；明显 24/25 旧帖且无新信息 → 跳过或仅作 D 线索，不入库 |
| **公司规模** | **排除**初创、无名工作室、代面小作坊、公司名含糊无法归入品牌的帖；**可收**：`qiuzhao/data/company_tiers.json` 已登记大厂/中厂/小厂品牌，及同量级知名厂（即使本轮才新建题库） |
| **禁止堆库** | 不向 `初创小厂-Agent面经题库` 继续堆新帖 |

## 通用题 vs 项目题（入库口径 2B）

- **入库**：可脱离对方项目复用的技术题；行为面（动机、反问、软技能）可收。
- **不入库**：绑定对方具体项目/函数/实现细节的问法（如「你项目里某某函数怎么写」「介绍你的某某系统架构细节」）。
- **可抽象则改写后再入库**：例「你项目里意图识别怎么做」→「对话系统意图识别：规则 / 小模型 / LLM 分类各自适用场景？」；改写后归入 `#Agent`/`#RAG` 等，**不要**堆进 `#项目深挖` 除非确是可复用的深挖模板且不含对方项目细节。
- `#项目深挖`：仅收可复用的考察模板（如「如何划分独立负责与协作部分」），禁止写入他人项目专有名词与实现细节。

## 题库纪律（强制）

若向 `公司面经摘录/{公司}-Agent面经题库.md` 增补题目：

- **仅**追加 `#类型` + 编号问题列表；
- **禁止**写入答案、考察点长文、每题来源块（与 `qiuzhao-assistant` 一致）；
- 手撕只更新 `高频手撕清单.md` 的**知识点节**，公司库 `#手撕` 只列规范题名并回链清单。

「考察点 + 来源 + 证据等级」的完整分析只写在 `08_面试准备/.../常见问题与面经汇总.md`。

### 统一 `#类型`（公司题库）

| `#类型` | 用途 |
| --- | --- |
| `#行为面` | 自我介绍、动机、软技能、反问 |
| `#项目深挖` | 经历/项目细节（非纯八股） |
| `#RAG` | 检索、分块、评测、知识库 |
| `#Agent` | 规划、工具、多 Agent、记忆、MCP/Skill |
| `#模型与训练` | 训练、对齐、推理、评测指标 |
| `#工程与系统` | 后端、并发、存储、部署、可观测 |
| `#业务与产品` | 业务理解、产品取舍 |
| `#手撕` | 算法/设计题名 → 详表进手撕清单 |

可增补类型，但须在 Skill 与题库标题中写清；历史别名（如 `#架构与Agent设计`）新写入时优先归并到上表。

## 工作流

### 1. 确定公司与岗位

1. 从主控取得公司、岗位、情报卡、时间范围/平台/文件名等可选约束。
2. 无法唯一确定则停止并确认。
3. 完整读取情报卡 JD，提取：公司全称/简称、岗位名与同义名、业务线、职责与能力关键词。

### 2. 本地优先

1. 若存在 `{公司}-Agent面经题库.md`，完整读取问题列表，纳入候选并标注来源类型为「本地题库」。
2. 查阅 `03_面经/{公司}-面经与复盘.md` 中已有问题行（不抄写外部长文答案）。
3. 若岗位偏 Agent/RAG，可参考 `DORA面试手册` 相关页，标注为「项目手册补充」，不得冒充该公司面经。

### 3. 来源链接库书签（强制）

1. 读取 `来源链接库.md` / `source_links.json`。
2. 优先打开 `status=有效` 且 `type` 为「面经列表」「作者动态」或备注含面经入口的 URL。
3. 再扫与目标公司/岗位相关的汇总表、日程线索（情报向链接交给日更；本 Skill 只取面经相关入口）。
4. 书签打开失败 → 记「待核实」并继续其它入口，不得假装已读。

### 4. 生成检索词

「公司词 × 岗位词 × 招聘/面试词」组合：

- 公司词：全称、简称、品牌、业务线名。
- 岗位词：JD 原名、去届次/地点后的名称、岗位族、近义岗位。
- 招聘词：`秋招`、`校招`、`应届`、`面经`、`一面`、`二面`、`终面`、`HR面`、`群面`、`AI面`、`笔试`。

扩展顺序：精确岗位 → 同岗位族 → 仅必要时用同类公司同岗补通用题。不得让低相关结果淹没直接面经。

**缺口公司强制**：广扫或补库时，对「情报库已有 JD、尚无 `{公司}-Agent面经题库`」的品牌，必须用 **公司词 × 该卡 JD 岗位名 ×（面经/一面/秋招）** 检索；不得只用泛词 `Agent面经` 声称该公司已覆盖。近岗可降为 B；他司题不得冒充该公司高频。搜过无真帖则记「已检索无真帖」，不假装已读。

### 5. 外网多方搜寻

1. 优先复用用户已打开/已登录的牛客、脉脉、知乎（浏览器 MCP）；遵守其连接与认证规则。**禁止**访问小红书。
2. **强制多路径**：来源链接库书签 → 牛客（面试中心/作者动态/待续挖帖）→ 脉脉/知乎若可达则补；不得只扫单一平台就声称「多方完成」。小红书路径已停用，不算未完成平台。
3. **每平台**多组检索词并翻阅足够结果；不要只读首条；至少覆盖计划平台中可访问的多数。
4. 登录/验证码/权限受阻 → 明确告知需在哪个站点完成操作；不得绕过认证或用其他来源假装完成该平台检索。
5. 不读取密码/Cookie/私信；不高频批量抓取；单轮实质帖处理宜设上限（约 15–25 篇），列表扫过未点开的记线索。
6. 可补充官网招聘页，须标明来源类型。

### 6. 来源记录与证据层级

每条有效面经记录：平台、标题/描述、链接、日期、届次、轮次、是否本人经历、问题/流程/考察点、与目标岗位关系、可信度。

- **A**：同公司同岗（或高度一致）本人直接面经。
- **B**：同公司近岗或同岗不同届。
- **C**：他司同类岗，仅支持通用问题。
- **D**：二手转述/汇总帖，只作线索；**总结/卖课帖不得升级为 A/B**。

至少两个相互独立来源才称「高频/多次出现」。无法确认是否转载时不累计独立来源。不得大段复制原文；不得伪造帖子、日期或链接。

### 7. 入库整理 SOP（清洗 / 补全 / 分类 / 去重）

对拟写入公司题库或 `08_` 问题清单的条目：

1. **帖级过滤**：先过「帖子质量门」；总结/卖课/无题干直接跳过。
2. **清洗**：去掉广告、无关流程废话、水印口号；保留可考问的题干；按 2B 丢弃或抽象项目绑定题。
3. **补全**：模糊截图/残缺句补成可独立理解的完整问句；不确定处标 `[题干待核实]`，不臆造考点。
4. **分类**：归入统一 `#类型`；一手撕题进手撕分流。
5. **去重**：与已有编号题语义相同则合并（保留更清晰题干）；同义问法在 `08_` 可列 2–4 个代表问法，公司库只留 1 条规范题干。
6. **手撕分流**：规范题名追加到 `高频手撕清单.md` 对应知识点节（同行可 `来源：公司`）；全局同名只保留一条并合并来源公司；公司库 `#手撕` 仅题名 + `[[高频手撕清单]]`。
7. **新公司**：可新建 `{公司}-Agent面经题库.md`，并在综摘「已拆入库」回链；禁止把 C 级他司题冒充该公司高频。

### 8. 提炼与合并（写 08_）

1. 先综合 A/B 级提炼最重要考察点；证据不足则降低结论强度。
2. 问题映射到主要考察点；按可信度与直接相关度排序。
3. 流程轮次、群面/笔试/AI 面等形式单独整理；推测不得写成事实。

### 9. 停止检索

主要平台与检索词覆盖后，连续多组高相关结果无实质新增时可停止。书签 + 外网均受阻时停止并列出未完成平台。

## 输出规范

默认：

```text
秋招/08_面试准备/{公司}-{岗位}/常见问题与面经汇总.md
```

同名已存在则询问更新或另存。结构：

1. **核心结论：最重要的考察点**（结论前置）
2. **检索范围与证据概况**（本地题库、来源链接库书签、各平台是否可达）
3. **直接面经综合分析**
4. **常见问题清单**（主问题、不同问法、考察意图、来源等级、独立来源数、轮次、相关度、准备提示、建议 `#类型`）
5. **其他有价值信息**
6. **低置信度与待核实项**
7. **来源清单**（A/B/C/D 分组 + 可点击链接）

无直接面经时写明检索范围，再用近岗补充并标注降级。

## 完成前检查

- 已读完整 JD；已扫来源链接库面经相关书签。
- 本地题库/复盘已优先利用；外网受阻已如实说明。
- 高频结论来自多独立来源；清洗/分类/去重已做。
- 产出在 `08_面试准备/{公司}-{岗位}/`；题库仅问题列表；手撕在知识点节。
- **本机双重备份已执行**（见下节）。云端改按 `qiuzhao-assistant`「云端仓库与笔记真源」写入 my-obsidian。
