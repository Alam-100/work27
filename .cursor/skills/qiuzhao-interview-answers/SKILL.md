# 自我介绍和回答（秋招专享）

## 目标

将岗位分析、常见问题与**可核验的项目事实**整合成可直接开口的面试材料。回答须岗位定制、事实可信、口语自然；明确区分「可直接说的答案」与「仅供准备的依据」。

**落盘与编排仍在秋招 vault**；项目深度来自 DORA 手册（及可选代码），不把本 Skill 迁到 DORA 仓。

## 输入与优先级

### 1. 确定目标岗位

从主控取得公司、岗位及可选文件名/风格。无法唯一确定则停止并确认。

### 2. 四类输入（前三类必需；手册强制）

1. **岗位分析文档**：优先用户点名；否则 `08_.../岗位分析与经历匹配.md`。
2. **常见问题文档**：优先用户点名；否则 `08_.../常见问题与面经汇总.md`。
3. **求职画像**：`秋招/00_画像/求职画像.md`。
4. **DORA 面试手册（强制）**：按下方「手册引用流程」打开相关模块；手册缺失或路径不可达 → **停止**并说明，不得仅凭画像摘要硬写技术深答。

任一 1–3 缺失 → 停止并指出；建议先跑对应上游 skill，不得用其他公司材料静默代替。

### 3. 完整读取并建依据表

完整读取输入；建立内部表：问题、考察点、建议经历、画像证据、**手册覆盖标签**、可用数字、证据缺口。默认不重新联网；仅用户要求或时效事实必须核验时才联网。

## 手册引用流程（强制）

在写自我介绍卖点与逐题技术答之前必须完成：

1. 读 `MAP.md`（或 README）确认模块完备度与阅读路径。
2. 根据岗位分析卖点 + 常见问题主题，映射到相关模块（可多选），例如：
   - RAG / 检索 / 分块 / 评测 → `01-rag-knowledge`
   - Agent / 规划 / 工具 / 记忆 → `02-agent-core`（及必要时 `04-task-goal-planning`）
   - 旅行 / 多 Agent / 地图 → `03-travel-multi-agent`
   - 可观测 / 安全 → `05-observability-and-security`
   - 前端流式 / 状态 → `06-frontend-streaming-and-state`
3. 每个相关模块至少读：`00-overview.md`；有深挖篇则按需读 `01`–`05` 中与题相关的节；刷对应 `06-interview-qa-bank.md` 的覆盖标签与口述要点。
4. **覆盖标签纪律**：
   - `已落地` / `部分落地`：可写入「建议回答」，部分落地须划界说明。
   - `未做-演进` / `不适用`：只能写诚实划界或「计划/不做原因」框架，**禁止**包装成现网能力。
5. `07` / `GAPS-INDEX` 仅作「别夸大」对照，不当讲稿。

产出文档的「输入文件」节须列出实际打开的手册路径（模块 + 文件名）。

## 可选代码核对

在以下情况打开 DORA 代码仓核对（只读，默认不改代码）：

- 手册写「已落地」但口述需要类名/模块路径/调用链；
- 用户明确要求「对照代码」或「别只背手册」；
- 画像/手册表述冲突，需用代码裁定是否夸大。

核对后若发现手册过时：在产出中标 `[手册待更新：…]`，**不**在本 Skill 内擅自重写冻结深挖篇（改手册走 DORA 侧 `dora-interview-manual-sync` 或用户点名任务）。

## 事实与定位规则

1. **求职画像**：身份、履历时间线、量化结果、简历表述的最高依据。
2. **DORA 手册**：项目设计动机、权衡、踩坑、技术题口述与覆盖边界的最高依据（技术深度优先于画像里的一句话 STAR）。
3. **岗位分析**：决定对岗方向与主卖点，不得覆盖/修改画像或手册事实。
4. **常见问题文档**：决定题目范围与优先级；须覆盖全部问题组。

冲突裁决：

- 履历数字/角色 → 以画像为准，列入待确认；
- 是否已落地/边界 → 以手册覆盖标签为准；代码核对可降级「已落地」为「部分/待确认」；
- 岗位分析建议使用画像或手册没有的经历/数字 → 不采用并标缺口。

严禁虚构、补全或夸大个人事实；严禁把 `07` 缺口写成已交付能力。

## 撰写自我介绍

### 两分钟中文

围绕岗位分析的 2–3 个核心卖点：身份与应聘岗位 → 最相关经历与证据（优先手册已落地能力 + 画像量化）→ 关键行动/量化结果 → 为何支撑该岗 → 简洁动机收束。约 400–500 字起步，按自然语速校准约两分钟。

### 一分钟英文

同一定位重新组织，不逐句直译。约 120–150 词起步，校准约一分钟。事实与中文完全一致。

### 检查

开头直接；每卖点有画像或手册依据；与岗位分析优先级一致；能自然说出口；未把未做能力写进介绍。

## 回答常见问题

1. 按常见问题文档的可信度/相关度顺序处理**全部**问题组；合并问法不重复答案。
2. 每组结构：代表性问法 → 考察意图 → **建议回答**（可口述）→ 事实依据（画像段落 / 手册模块文件 / 可选代码路径）→ 可能追问 → 风险或待补充。
3. 行为题用精简 STAR；动机题用「结论—岗位理解—证据—贡献」；公司业务题以岗位分析已核验信息为界；**项目深挖题优先复用手册 00/深挖/06 口述要点**，再口语化。
4. 口语：先答后证；一般 45–90 秒；同经历多题换切入角。
5. 证据不足：谨慎用不夸大证据，或给安全框架并标 `[待补充：…]`；文末集中列出待补充项。

## 输出规范（默认 Markdown）

写入：

```text
秋招/08_面试准备/{公司}-{岗位}/自我介绍和回答.md
```

同名已存在则询问更新或另存。文档顺序：

1. 标题与岗位信息（公司、岗位、日期、输入文件含手册路径）
2. 面试定位摘要（一页内可浏览）
3. 两分钟中文自我介绍
4. 一分钟英文自我介绍
5. 常见问题与建议回答（按主题/优先级）
6. 待补充与待确认事项（含手册/代码核对备注）

仅当用户**明确要求** DOCX 时：输出 `自我介绍和回答.docx` 到同一 `08_` 目录；渲染逐页检查截断/重叠/乱码后再交付。PNG/PDF 中间件只放 `qiuzhao/tmp/`。
